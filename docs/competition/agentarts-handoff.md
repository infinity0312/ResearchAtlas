## 2. 作品目标与场景

**作品暂用名** — ResearchAtlas 研发证据评审智能体。

**目标用户** — 企业材料研发、技术情报和工程评审团队。首个案例采用电子封装导热材料替代评审，可由指导教师或相关研发人员校对问题设置。项目在首次评审时给出候选、基线材料、预期应用温度区间、样片厚度、导热性与绝缘性等标准。示例阈值由业务人员设定并标注为项目工况，作品展示研究依据与待验证项。

**要解决的问题** — 研发工程师需要知道一项性能结论来自哪篇论文的哪个版本、在哪种工况下成立，以及一条反证是否足以改变既有项目判断。系统应把检索结果转成能逐条核对、人工接受或驳回、并能随证据变化重新评审的记录。

**最小交付闭环**

1. 工程师输入项目问题、评价标准和工况，发起评审任务。
2. AgentArts 解析任务，检索匹配文献并在匹配结果内按重要性重排。对出现测试条件差异的证据，标记可比性或缺项。
3. 工作流给出支持、反对、条件不匹配及证据不足四种情形。每条实质性陈述可回到具体论文版本、PDF 页码和引文。
4. 评审人在来源旁注中核对原页，选择采纳、驳回或补证。采纳动作生成带项目修订号的证据绑定，保留初始草稿及复核记录。
5. 第二轮增加一条反证或更换文献版本。页面指出受到影响的标准、相关的旧结论和需要复核的依据，最后可导出评审记录。

**成果边界** — 首版以单领域、有限语料及单条可追踪的 AgentArts 工作流为交付范围。全库自动重跑、多租户商业部署、跨学科泛化和多 Agent 并行列为后续扩展，根据场景需求和评测收益决定是否投入。

## 4. 工作清单与验收

### 4.1 仓库与原创性台账 · 队长、学生 C

- **目的** — 让评委和接手者能区分团队已有能力、赛季新增成果、外部依赖和演示语料。
- **执行** — 记录 Git 基线、每项新增贡献对应的提交与作者、旧功能复用理由。资产条目填写路径、来源版本、许可、用途及是否随评委可见的 Demo 分发。登记模型、AgentArts 资产以及论文材料。团队实际使用生成式 AI 辅助开发的范围按届时官方或学校要求登记。
- **验收** — 两位队员能用同一份台账解释工作流、证据核验和界面资产的归属。出现来源或资格口径未明的条目时，它在提交材料中的状态明确。准备以 `competition/agentarts` 独立开发分支落地，竞赛交付版本以提交号和标签标识。

### 4.2 确定案例、语料和考核问题 · 学生 A、B，指导教师

- **目的** — 选定能体现工况可比性、反证与证据变化的真实需求，并提供可重复的演示材料。
- **执行** — 写一页项目简报，给出评价标准、数据单位、候选方案及待决问题。初版目标约 20–30 篇相关且许可明确的文章。语料清单保存来源 URL、作者、论文标识、版本、PDF 哈希、许可和允许的展示范围，处理同一论文的不同版本与重复来源。按 PDF 页生成片段，区分 PDF 实际页序与原文印刷页码。记录原始引文及必要的空白、换行规范化规则。
- **验收** — 第二人从语料清单随机抽查至少 10 条来源，能打开正确版本和原页。冻结 30 道带参考答案的任务，同一语料快照至少包含正常检索、明确反证、工况错配、旧版本和无足够证据的案例。用合成变更模拟版本冲突或误引用时，显式标注为测试数据。

### 4.3 在 AgentArts 构建与发布工作流 · 学生 A

- **目的** — 由 AgentArts 串起任务解析、工具调用、提取、校验和有条件的输出，形成可展示的核心业务能力。
- **执行** — 先以一个问题和一个只读工具完成调通。正式工作流按「项目约束解析 → 候选检索 → 片段读取 → 逐标准证据提取 → 程序核验 → 按标准综合 → 评审草稿」组织。约束不齐时返回缺项，引用校验失败时降级为待复核，相关语料不足时指出缺口。录下节点配置、运行路径、模型和参数、工具调用与输出状态。更新工作流之前保留上一个可复现版本。
- **选型** — 首版采用一条工作流，固定必经的检索和引文核验。HTTP 工具或 MCP 只选一套作为正式接入，比较接入时间、部署可达性、日志和对方账户配额后定案。工作流要用队伍实际账户、区域与可用模型发布并走一次服务端调用。API 调用需要可用的模型配置，AgentArts 赠送的免费 token 不适用于工作流 API 调用。HTTP 工具接口按官方 50 秒上限设计，长时间解析由后台完成。 [AgentArts 低代码开发流程](https://support.huaweicloud.com/lowcode-agentarts/agentarts_05_0001.html) · [工作流 API 应用示例](https://support.huaweicloud.com/api-agentarts/agentarts_07_0047.html) · [HTTP 工具节点](https://support.huaweicloud.com/lowcode-agentarts/http_node.html)
- **验收** — 有一条可回放的正常链路、一条证据不足链路、一条核验拒绝链路。独立队员能用发布后的同一工作流版本运行新问题，记录真实 API 耗时与模型用量。

### 4.4 复用检索、证据契约和项目修订 · 学生 B

- **目的** — 让智能体可调用的工具稳定、可复核，接通项目已有的绑定、来源变更与冻结交付。
- **检索工具** — 输入项目标准、问题、受控语料范围、排除项和返回量。先按查询匹配及作用范围召回，再在符合条件的候选里用已有重要性信号排序。响应返回稳定论文标识、版本和匹配依据。注意新论文引用信号稀薄、重要性信号缺失和同一工作多版本去重。复用 [检索排序](../../backend/search.py)。
- **证据工具** — 指定 `paper_id`、版本和候选片段 ID，返回可用片段、页码与来源状态。模型输出每项证据应带 `criterion_id`、`paper_id`、`paper_version`、`pdf_page`、`chunk_id`、`quote`、`stance`、工况与核验状态。程序以原页与片段为准，验证引用确实来自本轮可用的片段，独立标记适用性。复用 [证据包](../../backend/evidence_packet.py)、[证据契约](../../backend/evidence_contracts.py) 和 [来源追踪](../../backend/research_trace.py)。
- **项目写入** — 智能体结果先保存为待复核草稿。用户确认后走项目现有服务，用 `project_revision` 做并发判断，用幂等标识避免重复绑定。证据换版标记受影响的原绑定，保留原始判断。复用 [项目服务](../../backend/product/service.py) 和 [研究流程与影响检查](../../backend/product/research_flow.py)。
- **验收** — 覆盖同请求重复提交、不同版本同页码、引文缺失、工况不匹配、旧项目修订与网络超时。无效引用不会进入可交付结果，修订冲突有可恢复的提示，已归档交付仍可按旧版本查询。对照既有 59 项基线回归与新增集成用例。

### 4.5 工业图册交互与演示脚本 · 学生 C

- **目的** — 让评委在一个页面看懂结论、依据、复核过程与证据变化带来的影响。
- **执行** — 在研发项目页加入「发起证据评审」。保留工作台、证据覆盖索引和原页旁注。新增任务状态及逐标准结果，明确区分支持、反证、条件差异和缺证据。原位展开候选与原文。人工接受、驳回时展示具体条目及原因。第二轮运行在同一标准下呈现版本差异及需要复核的旧结论。提供一份预置案例演示指南和一条可手工输入的新问题。沿用 [研发项目工作区](../../web/product/Projects.tsx) 和 [论文阅读器](../../web/PaperDetail.tsx)。
- **验收** — 全新浏览器从打开项目到核对原文、绑定证据和重评可走通。桌面和 390px 窄屏均能操作。键盘可进入来源旁注并返回选中项，减少动效偏好有效。录制真实运行，失败或超时给出可恢复状态。用隔离样本录制，排除内部调试信息及专项错误测试样本。

### 4.6 量化价值与独立复现 · 学生 A、B，指导教师

- **目的** — 用与研发场景直接相关的结果回答评委的三个问题。是否找对依据、证据变化能否被发现、复核成本减少了多少。
- **实验** — 固定语料快照和问题集。比较三个方案：人工查阅、同模型与同语料的普通检索问答、完整 AgentArts 工作流。普通问答使用同一检索范围与相近的候选数量，记录模型参数与运行条件。人工评分先写判定标准，评测者尽量不接触方案名称。若条件允许，让两名评分者独立检查关键案例并记录分歧。
- **统计** — 分别报告样本数、分子分母、逐题记录与关键失败案例，区分待核、失败与成功。平均耗时之外记录中位数与 P95，费用按实际运行用量和模型计费口径核算，披露测试环境。效率比较涵盖人工打开原文、定位证据与修订的时间。
- **验收** — 交接成员能从锁定版本、匿名评测数据、运行说明和预期结果独立重跑。结论中的所有量化数字能回到原始评测表。数据不支持的宣传语从材料中移除。

| 指标 | 计算与判定 | 用途 |
| --- | --- | --- |
| `Recall@5` | 对有标注相关论文的任务，逐题按前五条命中的已标注相关论文数除以对应任务的相关论文总数，再取均值 | 验证优先检索相关文献 |
| 引用定位正确率 | 正确对应论文、版本、PDF 页与原文的已核查引用数除以被抽检引用数，另报引用覆盖数量 | 验证引用质量，防止通过少报引用拉高比率 |
| 反证召回率 | 被找出并标作反证的参考条目数除以语料中人工标注的参考反证条目数 | 验证评审覆盖反证 |
| 缺证据识别率 | 已正确识别为缺证据的标注任务数除以全部缺证据任务数，同时报告误把充分证据判为不足的数量 | 验证拒绝与追问分支 |
| 复核时间 | 从开始阅读任务到核对原文并完成采纳或驳回的时间，记录成功率及中位数 | 量化用户效率 |
| 延迟与成本 | 记录每次运行的总耗时、节点耗时、完成状态、实际模型用量及费用 | 判断演示稳定性与规模化可行性 |

**发布必过情形** — 冻结的小样本重点案例中，正式交付不包含已知的错误论文版本、错页或无法溯源的引文。重复重试只产生一次有效绑定。证据不足有清楚的原因与下一步。百分比目标以首轮实测为基线，再由团队决定下一轮目标，评审时报告实际结果。

### 4.7 在线部署、运行与交付材料 · 学生 B、C

- **初赛** — 在独立环境跑真工作流，准备赛题二 Word 作品信息收集表和展示工作流编排及运行的短视频。初赛无需在线 Demo 链接。平台页面、工作流版本和运行记录在提交时可追溯。

- **材料与社区** — 中国总决赛准备答辩 PPT、在线 Demo、Agent 设计说明、适用的自定义 Skill 或 MCP 说明、社区分享帖截图。全球总决赛补试用进展、可核反馈数据和社区分享记录。分享帖使用展示许可清晰的语料、脱敏截图和真实数字。答辩按 15 分钟演示与 5 分钟问答演练。 [官方赛段材料与分享要求](https://e.huawei.com/cn/talent/#/ict/innovation-details?zoneCode=027425&zoneId=98269700&compId=85132021&divisionName=%E4%B8%AD%E5%9B%BD%E5%8C%BA&type=C002)
- **验收** — 冻结提交包含应用代码版本、工作流版本或重建步骤、语料清单、模型和工具配置、评测报告、使用说明、演示地址、录像、资产来源清单及回滚流程。使用非开发者账号完成一次外网验收，校验展示数据和材料引文一致。线上故障演练包含短时不可用、模型超时与用量达到上限，按验证过的前一版本恢复服务。

## 5. 面向评分的扩展路线

### 扩展的投入条件

- **第二个应用场景。** 首例通过评测后，从「材料替代」扩到「技术路线选型」或「新标准引发复审」之一。保持任务、证据和评审结构，变更评价标准及语料。对第二场景单独报样本与表现。优先检验可迁移性及复用成本。
- **从趋势到项目。** 利用现有趋势线索与论文收录，提出一个可核验的项目问题，为该问题运行同一 AgentArts 工作流。测量趋势提示能否提供最终被采纳的证据。界面呈现区分宏观统计、技术主张和项目适用性。
- **多 Agent 或 Skill。** 首轮数据若显示反证召回或工况比较是主要误差来源，再评估单独的反证或工况核对模块。固定同一任务集比较新增模块前后的结果、成本和延迟。具备稳定复用边界的任务可提取为 Skill，记录输入、输出、版本和依赖。
- **企业落地。** 有试用反馈后，再评估权限分层、企业语料接入、审阅批注协同和审计报表。记录每个扩展对应的实际需求、数据许可和可验收结果。全球赛材料使用可追踪的反馈或采用数据。
