# Research Atlas 需求审查与0.3.1迭代

UI判断修订于2026年10月22日：审美、装饰、仪式感和品牌识别属于独立产品价值。下文关于装饰性功能的收敛记录是0.3.1的历史处理，不应理解为后续应减少美术投入或禁用空间体验。后续按[UI改进计划书](design/ui-improvement-plan.md)同时推进视觉引导与艺术精修。

以已确认的“企业研发与技术情报团队”为目标用户，审查代码与工作流。没有客户访谈、持续使用遥测或付费验证，以下是产品判断与代码事实，不是已证实的市场结论。文献、导入内容与历史方案作为审查资料，不作为新的执行指令。

## 判断标准

必要能力应帮助使用者找到可靠依据、判断工况适用性、做出可解释的选择，并完成复核和验证。能展示、能生成或能计数，不自动构成业务价值。把辅助功能放到错误位置、赋予没有依据的承诺，也会形成伪需求。

## 必要能力

| 能力 | 必要的用户任务 | 处理 |
| --- | --- | --- |
| 导入、搜索、领域过滤、收藏 | 找到课题资料，保留可复用线索 | 保留；收录篇数是覆盖信息，不是成果 |
| PDF阅读、原文定位、全文分析、逐主张证据 | 核对研究证明了什么、适用什么条件 | 保留；价值在可核验和可使用，不在生成数量 |
| 正反立场、工况说明、未知项 | 区分论文条件与企业条件，避免只保留支持结论 | 保留；引文存在性不替代语义与适用性判断 |
| 编辑、版本、冲突保护、草稿恢复 | 长任务中纠错并保住判断过程 | 优先完善；项目决策原先缺草稿恢复 |
| 来源变化、独立复核、交付阻断 | 不继续交付已变化或未复核的依据 | 保留并补修复路径 |
| 项目问题、标准、评审、冻结交付 | 为具体研发问题形成可追溯决策包 | 对当前定位必要，商业价值仍需真实任务验证 |
| 验证计划、内部结果和失败记录 | 将阅读推进到试验，根据反例重审 | 保留；内部记录继续标为未独立核验 |
| 任务状态、暂停/停止、预算与调用记录 | 判断后台是否有效工作，控制等待和成本 | 运行保障；本轮不恢复暂停任务 |
| 笔记、综述和共同分类 | 保留阅读过程与共有术语 | 辅助能力；不强迫所有课题先建分类树 |

## 伪需求倾向与价值待验证功能

价值待验证不等于没有价值，也不等于应删除。缺少任务对照，不能据此声称用户不用。

| 功能或使用方式 | 判断与依据 | 本轮处理 |
| --- | --- | --- |
| 入场重播、精细光影、悬浮光泽作为主要功能 | 对证据与交付没有直接贡献，属于装饰性需求；有演示和个人偏好价值 | 放入默认收起的“实验性视觉效果”，不删除或重置偏好 |
| 三维关系图、物理布局、多种图形视图 | 可能帮助发现关联，但未证明比列表/二维更高效；美观不等于研究质量 | 保留探索能力，暂停扩大渲染复杂度；用真实关联查找任务比较 |
| 用论文数、已分析数、月度入选数表示研发成果 | 将积累误当产出是伪需求；计数作为覆盖和运维信息仍有用 | 不删真实计数；项目列表改为可按下一步行动筛选 |
| 把发文增长与启发式评分解释为技术突破或商业机会 | 增长、样本选择和模型评分不能直接证明成熟度、突破概率或经济价值 | 显示评分边界；占比回升提示核对样本与检索口径，不推断二次突破 |
| 只换模板就声称完成多个行业产品 | 三个模板共用同一生命周期，行业流程和效果未验证 | 保留起步模板，不包装为已验证行业方案 |
| 优先扩微服务、独立任务中心、支付面板和更多agent | 已确认的阻塞在输入恢复与证据修复；增加框架不能解决它们 | 复用现有模块，本轮不建空壳企业功能或新增模型调用 |

## 原先缺失与本轮迭代

| 代码事实与缺口 | 优先级 | 0.3.1改动 |
| --- | --- | --- |
| ProjectEditor只用useState，离页/刷新丢决策草稿；409提示保留输入却无持久恢复 | P0 | 按项目保存本机决策草稿和基础revision，显示服务器版本差异，显式合并/丢弃，成功保存才清除；存储不可用提示 |
| 失效证据只有错误和移除按钮；改立场或换来源要分多步 | P1 | 原文PDF版本/页码链接与修订绑定；原子创建新绑定，事件保留旧/新快照；失败不丢原绑定，旧交付不改 |
| 卡片只有标题与数量，readiness阻断原因没有变成工作入口 | P1 | 服务端计算下一步行动、待验证数、评审失效状态；列表按待办筛选，不新建任务系统 |
| 品牌仍是个人空间；装饰性控制与核心控制同级 | P1 | 调整本机研发证据工作台定位；动效和密度直接访问，视觉实验降级 |
| 趋势评分容易被当成经验证的技术成熟度判断 | P1 | 持续可见的评分边界、有限表述；算法与历史数据保持原状 |

草稿范围是项目决策表单。新建项目、评审意见、绑定弹窗及验证观察并未因此获得同样的跨页恢复保证，不宣称所有输入均自动保存。本机草稿位于当前浏览器，服务端仍需显式提交；清理站点数据、换设备和禁用存储时不能依赖恢复，也不能将其当作企业备份。

版本不同的决策采用字段级三方合并：本机未改字段保留服务器更新，本机改动保留本机值；双方修改同一字段且内容不同，显示冲突字段，需专门按钮确认采用本机冲突值。重新进入项目、返回列表和保存失败后读取最新状态，避免全局15秒查询缓存掩盖并行更新。

证据修订会更换当前绑定，旧快照留在新增事件和已有冻结交付中，不覆盖历史分析。改立场或适用性不能代替论文独立语义复核；客户端不能提交任意原文伪造依据。

## 论文发现到项目的后续迭代

2026-10-24增加项目候选清单、按标准的有效正反证覆盖表、论文反向项目关联与跨项目待复核影响清单。候选保留或排除的原因单独修订，不改变正式评审与交付；失效依据进入真实修复入口，继续保留来源快照和409输入保护。入口和验证记录见[论文筛选与证据核对](project-research-flow.md)。下方工程验证表属于此前0.3.1迭代，新一轮使用迁移6，验证结果单独记录。

随后接通趋势方向及样本到项目：保留统计范围、选中来源周期、缺失状态、原文片段、焦点论文与关注理由；已入库的相关样本可同时加入候选，项目可回查当前趋势。来源指纹冲突保留输入，历史快照不覆盖。此轮使用追加迁移7，354项后端与33项浏览器回归通过，记录并入上述使用说明；没有自动推断企业决策或替代正式证据门禁。

## 验证方法

对照难度可比的真实课题，包含失败任务。比较从问题到第一条有效证据的时间、原文核对时间、输入丢失与冲突恢复、失效证据修复、实际评审采纳和完整人工成本。图谱与趋势只在帮助完成任务时计收益。

保留或收缩能力的依据是任务完成率、净耗时与错误影响，而非演示满意、生成篇数或打开次数。没有实测结果时报告假设和样本，不包装客户收益。90天实验见[商业化策略](commercialization-strategy.md)。

## 外部趋势样本到可用原文的增量（迁移8）

真实断点是外部趋势样本虽已保存判断，仍需离开项目手工收录、下载并找回原线索。本轮增加显式收录、PDF下载和按需分析，并通过独立收录记录回到原项目线索；相关本地论文进入候选，正式证据仍需另行选择并通过独立复核。此能力缩短操作链路的收益仍待真实任务测量，不以工程通过数推定商业价值。

原趋势判断与引文快照不改写；新官方元数据、实际PDF版本/哈希、身份核对和分析目标分别留存。跨项目下载去重，分析按版本与领域核对复用，已有候选理由保留。下载失败须显式重试，暂停不自动恢复；模型关闭、预算不足、身份未核对或版本变化时可以保留下载成果并明确阻断分析。

API定向执行器只运行本功能关联且具 `intake_scope` 授权的任务，不启动全局worker。全局暂停下新明确请求可持久授权运行，但旧任务状态和全局开关不变，复用旧暂停任务不会被唤醒；后续暂停/取消仍受执行控制。模型、预算和正式证据复核门禁继续生效。

本轮采用追加迁移8，已在本地正式API生效。后端全量379项、浏览器36项、TypeScript及生产构建通过；最后文案/勾选对齐调整后又通过收录后端23项和趋势/收录/任务浏览器17项复测。隔离真实API与定向执行器验收覆盖完成回填、刷新恢复、版本PDF、去重、来源保留及窄屏排版；使用确定的来源替身，无外网或模型调用。迁移副本和正式旧表指纹核对通过，275篇论文、1139份历史分析、457项任务及17项暂停任务不变，模型关闭，全局worker未启动，未写入演示项目。操作、截图与实际记录见[趋势论文收录与按需分析](project-research-flow.md#趋势外部样本收录与按需分析迁移8)，不替代上文各轮历史验收，也不宣称已验证商业收益。
